# Phase 2, étape 2.4 — Production automatisée

Mise en place le 02/10/2026. Les départements sont calculés en parallèle sur
GitHub Actions, et le jeu est publié hors de Git
([ADR 0011](../adr/0011-production-github-actions.md)). Les identifiants
sont conservés d'une version publiée à l'autre
([ADR 0012](../adr/0012-identifiants-stables.md)).

Cette étape absorbe l'ancienne étape 2.3 : son premier vrai lancement porte
sur les 8 départements de l'**ex-Midi-Pyrénées**, désormais en ligne.

## Lancement

Sur GitHub : *Actions* → *Production* → *Run workflow*, avec trois
paramètres :

- les départements (codes INSEE séparés par des espaces, ou `all`) ;
- la publication ou non ;
- le nombre de départements calculés à la fois (4 par défaut).

| Étape | Rôle |
|---|---|
| `prepare` | Extrait OSM France (Geofabrik), renumérotation des nœuds, découpe par département, dépôt dans la release `osm-extracts` |
| `department (CODE)` | `flat-segments department` sur l'extrait du département |
| `assemble` | `export-pmtiles --previous` (identifiants de la version publiée conservés), dépôt dans la release `data-latest`, lancement du déploiement Pages |

Le tableau récapitulatif et le bilan des identifiants sont dans le résumé du
lancement.

## Incident : mémoire de la découpe

Le premier lancement sur les 8 départements s'est arrêté 38 s après le début
de la découpe : le *runner* (16 Go) n'avait plus de mémoire.

- **Cause** : `osmium extract` réserve, par extrait, deux fois le plus grand
  identifiant de nœud divisé par 8. Cela fait 3,7 Go par département avec des
  identifiants de plus de 14 milliards.
- **Correctif** : renuméroter d'abord les nœuds (`renumber-osm`).
  - Les voies gardent leurs identifiants OSM.
  - Le réseau obtenu est identique : vérifié sur la Haute-Garonne.
  - La renumérotation de la France a pris 5 min, et la découpe des 8
    départements en un passage 2 min.

## Données retirées de Git

Le site lit désormais le jeu de la release `data-latest`.

- `web/data/segments.pmtiles`, `segments.json` et `ids/` sont retirés du
  dépôt. L'exception à la limite de 1 Mo des *hooks* pre-commit disparaît
  aussi.
- Seul reste le jeu d'exemple fictif (`web/data/sample/`), utilisé en local
  et quand la release manque.
- En local, on récupère le jeu publié avec :

```bash
gh release download data-latest --dir web/data && tar -xzf web/data/ids.tar.gz -C web/data
```
